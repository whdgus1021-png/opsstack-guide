Automate the monthly client report

Sheets, Looker Studio and one scheduled workflow. A day of setup, then about fifteen minutes per client per month — and a fixed, boring schema that survives staff changes.

Why this build, not a dashboard tool

The paid reporting tools are good and start around the price of a small retainer. What most agencies actually need is one repeatable view that answers the client's six questions and arrives on the same day each month. That is a Google Sheet, a Looker Studio report, and a scheduled workflow that pokes both.

Total cost: $9/month (Make Core, annual billing) for any number of clients you can fit in 10,000 credits — roughly $1.13 a client at eight. Everything else is free.

Real cost: a day of setup, and the discipline to keep one column schema for every client instead of a bespoke sheet per account.

Step 1: fix the schema before you touch a chart

The reason most reporting builds collapse is that every client gets a slightly different sheet, so every month is a small bespoke job. Pick one row shape and refuse to change it per client. Ours looks like this:

One row = one client, one month, one channel
ColumnTypeWhy it exists
clienttextExact match with the report's filter — case and spacing matter
monthYYYY-MMSortable, aggregatable, no locale ambiguity
channeltextSEO / Ads / Referral / Email — the dimension most clients ask about
sessionsnumberVolume
leadsnumberConversion volume
deals_wonnumberThe number the client's finance person checks
revenuenumberAttributed revenue, no currency symbols
hours_spentnumberYours; feeds the internal profitability view
retainernumberYours; monthly fee, constant per client

A starter file with sample rows is here (CSV) — import it into a fresh sheet and replace the rows.

Two rules that save months of pain later: no formulas in the raw tab (formulas belong in a separate tab, or the data source starts returning errors when rows are appended), and no merged cells, ever — Looker Studio treats a merged header as a data type it cannot guess, and you will spend an hour on it.

Step 2: one sheet, or a tab per client?

Both work; they fail differently.

Structure choice
StructureGood forBreaks when
Flat data tab (all clients, all months, one table)Up to ~30 clients; one report with a client filter; any aggregation across clientsSomeone deletes a row and the report silently loses a month
Tab per clientClients with genuinely different metrics; strict access separationYou have 20 tabs to update by hand, and Looker Studio needs 20 data sources

We default to the flat tab. One data source in Looker Studio, one filter dimension, and a month-end append that touches one row per client per channel. Access separation, if a client insists on it, is a separate file with an IMPORTRANGE — not a separate schema.

Step 3: build one report, copy it

Connect Looker Studio to the sheet once. Then build a single page that answers six things and stop:

  1. Month vs previous month on sessions, leads, and revenue — three scorecards, with the change shown as a number, not a colour.
  2. Channel table with sessions, leads, deals and revenue, sorted by revenue.
  3. Lead-to-deal rate by month, as a line chart. This is the number clients argue about, and it is the one most reports omit.
  4. Cost per lead if you have spend in the sheet; otherwise hours against retainer.
  5. Twelve-month trend for context, because one month is noise.
  6. A one-line note field from the sheet: what changed, what is next. Nobody reads a dashboard that does not explain itself.

Then add a client filter (a drop-down on the client dimension) and either share one report with the filter preset per client, or copy the report per client and set its filter as default. Copies are safer for client-facing links: a filter is a URL parameter, and a URL parameter gets forwarded to the wrong person eventually.

The caching trap

Looker Studio does not read your sheet every time someone opens the report. A Sheets data source has a freshness setting measured in hours, and the default is long enough that a number you corrected this morning may not show this afternoon. Set data freshness explicitly on the data source, and remember that the Extract Data connector is the opposite tool: it freezes a snapshot, which is right for a closed month and wrong for a live dashboard. If a client says "these numbers are from last week", this setting is the answer nine times out of ten.

Step 4: the month-end workflow

The Make scenario does four small things and stops. Keep it that small; the temptation to make it clever is what turns a reporting pipeline into a maintenance item.

  1. Trigger: schedule, first business day of the month, 07:00 in your timezone.
  2. Read: the client list from a small config tab (name, report URL, contact email, retainer).
  3. Write: for each client, append a summary row to the archive tab — month, totals, and a status: sent flag. This is your audit trail when a client says the report never arrived.
  4. Send: one email per client with the report link and a two-line summary written from the numbers, not the dashboard.

That is about 25–60 credits per client per month on Make's counting. Eight clients is a few hundred credits against a 10,000-credit plan, which is why the whole stack fits in $9.

Two guardrails worth building on day one: an error handler that emails you (not the client) if a step fails, and a dry-run toggle in the config tab so you can test the month-end run without emailing eight people.

Automating that away is how agencies send reports with a tracking gap in them and spend the next call apologising.

When to stop building and buy

This build has a ceiling, and it is roughly 20 clients or three stakeholders per client. Past that you want white-labelled domains, per-client logins, scheduled PDFs with your logo, and a way to let a client's marketing manager log in without seeing anyone else's numbers. Those are paid features in dedicated reporting tools, and at that point the subscription is cheaper than the maintenance.

It also stops being the right answer if a client contract requires row-level security or an audit log of who viewed what. Google Sheets sharing is not that, and no amount of dashboard polish changes it.

FAQ

How much does this stack cost?

$9/month in total: Make Core at $9 (annual billing, 10,000 credits). Sheets and Looker Studio are free. At eight clients that is about $1.13 per client per month.

Why does the report show old numbers?

Caching. A Looker Studio Sheets data source refreshes on a freshness setting measured in hours rather than on every page load. Set it explicitly, and do not use the Extract Data connector for anything that should stay live.

Can clients log in and see only their own data?

Not reliably with a shared report and a filter — treat that as convenience, not security. For real separation, give each client its own report copy on its own data source, or move to a tool built for multi-tenant reporting.

Do I need Google Workspace?

No. A free Google account can own the sheet and the report. Workspace adds organisational sharing controls, which matter when staff leave — a shared Drive owned by a personal account is how agencies lose their reporting history.
